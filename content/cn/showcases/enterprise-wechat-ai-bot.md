**让客户的问题得到及时回应，让业务团队把精力留给需要人工判断的工作。**

在客户交付群里，采购方可能询问发货进度，现场工程师可能需要排查故障，员工也经常要查找内部流程。企业微信智能 Agent 可以结合企业知识库和业务系统，为这些重复性问题提供一个更便捷的服务入口。

本方案结合 AstrBot 与 [WeChat Native](/cn/projects/wechat-native-astrbot-个人微信接入插件/)，面向微信群及企业微信互通客户群等协作场景。WeChat Native 接入的是**个人微信账号**；具体互通范围和可用性需结合实际账号及群聊环境验证。订单查询、工单等业务能力需要按企业现有系统另行对接。

## 一个 Agent，支持客户服务与内部协作

| 场景 | Agent 可以协助的工作 |
| --- | --- |
| **客户答疑** | 基于产品手册、常见问题和售后规范，协助回答产品使用与常见故障问题。 |
| **订单与交付查询** | 对接企业业务系统后，按授权范围查询订单状态、发货进度等信息。 |
| **员工服务** | 在授权私聊中帮助员工查找报销、入职和内部办事流程。 |
| **业务协作** | 根据实际集成方案收集客户诉求，交由相关员工跟进需要人工判断的事项。 |

## 从回答问题，到协助完成业务任务

企业沟通往往需要结合上下文：客户可能先询问产品型号，再追问安装要求；也可能查完发货进度后，希望调整收货安排。智能 Agent 可以结合可用资料组织答复，并在授权范围内调用业务工具。

例如，客户在项目群里问：“设备出现 `E-402`，现场需要先检查什么？” Agent 可以从企业提供的故障排查资料中查找相关步骤，整理成便于现场人员阅读的回复。对于资料没有覆盖的问题，仍需工程师判断，不能把生成的回答当作最终诊断。

面对“我的订单什么时候到？”这样的问题，知识库本身无法提供实时结果。如果企业已提供查询接口，Agent 可以获取获准查看的订单状态，再结合问题组织答复。能查询哪些订单和字段，取决于身份验证及接口权限的设计。

## 让不同角色在熟悉的聊天入口协作

### 客户服务：常见问题及时响应

产品规格、安装步骤和售后政策往往分散在手册与文档中。将适合对外使用的资料整理为知识库后，Agent 可以协助处理重复咨询，让客服和工程师集中精力解决复杂问题。资料需要定期维护，回答质量也需要通过实际问题持续验证。

### 销售与交付：减少跨系统查询

销售或交付人员经常需要在客户群、订单系统和仓库之间来回确认信息。通过经授权的业务接口，Agent 可以把订单状态等信息带回对话；遇到改期或变更收货地点等请求时，可先收集必要信息，再交由员工处理。具体是否生成工单、如何通知负责人，取决于集成方案。

### 内部员工：让常用流程更容易找到

员工可以通过授权私聊询问报销要求、入职资料或其他内部流程。对内和对外的资料及接口需要分别规划访问权限；权限范围应在上线前测试，而不是仅依靠提示词约束。

## 在客户群里按需回应

客户群里既有日常交流，也有需要跟进的问题。Agent 的回应方式和访问范围可以结合业务场景配置：

- **按需触发：** 群聊可配置为仅在用户真正 `@` 机器人时回复，减少对日常交流的干扰。
- **区分对话上下文：** 启用独立会话配置后，同一群内不同成员可使用各自的对话上下文。
- **控制访问范围：** 通过用户和群聊白名单，限制可以与机器人交互的范围。
- **处理撤回和发送异常：** 插件会处理待处理消息的撤回，并在发送前检查原消息；发送状态不确定时查询回执，避免盲目重发。


## 示例场景：从订单查询到人工跟进

下面是一个可根据企业需求建设的业务流程，并非开箱即用的 ERP 功能：

1. 客户在授权群中 `@` Agent，询问订单 `PO-2026-108` 的发货进度。
2. Agent 根据问题调用企业提供的订单查询接口，获取当前用户获准查看的信息，并在群内回复。
3. 客户再次 `@` Agent，提出更改卸货地点的请求。Agent 结合该用户的对话上下文收集诉求。
4. 如已对接工单系统，Agent 可以生成待审核的请求，交由员工确认和处理；正式订单变更仍按企业设定的权限及审批流程执行。

## 如何规划 Agent 的权限与人工协作

不同任务适合不同的处理方式。试点时可以先划清服务范围，再根据业务验证结果逐步扩展：

| 任务类型 | 建议处理方式 | 上线前需要确认 |
| --- | --- | --- |
| **知识库答疑** | 从已审核的资料中查找并整理回复 | 资料是否适合目标用户查看，更新后如何维护 |
| **业务数据查询** | 通过受控接口获取必要字段 | 如何核验提问者身份和数据访问权限 |
| **变更与异常请求** | 收集诉求，交由员工审核处理 | 谁负责接收、确认和后续反馈 |

例如，查询发货状态和修改正式订单需要不同的权限。即使两个请求出现在同一段对话里，企业仍可只开放查询接口，把变更操作留在现有审批流程中。人工跟进的入口、通知方式和响应责任也需要结合现有系统设计。

## 部署与试点

- **数据与隐私：** WeChat Native 的状态库与插件日志不保存聊天正文和 Token。AstrBot、模型服务及其他组件的数据处理方式取决于各自的部署和配置。
- **当前接入范围：** 插件支持文本私聊和群聊回复，暂不支持自动解析图片、语音和文件。
- **从小范围开始：** 可先在内部测试群验证知识库答疑和触发策略，再按需对接只读查询并选择客户群试点。

一个务实的试点可以先选定一类问题，例如产品安装 FAQ 或发货状态查询。整理资料与权限后，用具有代表性的问题检查回答、群聊触发和异常处理；确认负责人及反馈方式后，再邀请少量客户参与。试点过程中收集未解决的问题和需要人工介入的情况，用于改进知识库和业务流程。
