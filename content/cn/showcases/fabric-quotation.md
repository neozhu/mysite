## 还在依靠 Excel、邮件和人工工程交接完成织物报价？

对造纸织物制造商而言，一份报价取决于客户的纸机、使用位置、织物设计和商务规则。信息分散在不同表格与沟通记录中，每一次交接都需要重复整理。

- 产品与纸机资料散落在多个 Excel 文件中。
- 销售依赖资深应用工程师判断合适的织物配置。
- 技术建议通过邮件或临时沟通传递。
- 定价规则和历史价格难以统一掌握。
- 折扣申请缺少清晰的审批记录。
- 多个报价版本难以比较和追溯。
- 关键应用知识集中在少数资深员工手中。

Fabric Quotation 将这些资料和决策纳入销售、应用工程师与商务审批人员共享的流程。

## 从客户询价到最终报价，一套流程贯穿全程

通用 CPQ 围绕**配置 → 定价 → 报价**展开。Fabric Quotation 是面向 PMC 企业的垂直 CPQ 与应用工程平台，覆盖造纸织物销售所需的完整业务链路。

<ol class="fq-workflow" aria-label="PMC 报价流程">
  <li><strong>1. 客户询价</strong>从客户需求出发。</li>
  <li><strong>2. 工厂 / 纸机 / 位置</strong>明确实际使用场景。</li>
  <li><strong>3. 织物选型</strong>选择对应位置的产品。</li>
  <li><strong>4. 应用工程评审</strong>逐项评审报价明细。</li>
  <li><strong>5. 设计建议</strong>完成技术配置与推荐。</li>
  <li><strong>6. 标准定价</strong>应用价格并保留快照。</li>
  <li><strong>7. 折扣审批</strong>审核申请的商务条件。</li>
  <li><strong>8. 客户报价</strong>形成决策可追溯的报价版本。</li>
</ol>

销售、工程和定价决策始终关联同一条报价明细，下一位参与者可以直接接续已记录的信息。

## 围绕 PMC 企业真实的业务方式组织信息

织物报价不仅是选择 SKU。每份报价都建立在客户实际的设备与应用场景中：

**客户 → 工厂 → 纸机 → 位置 → 织物**

从客户的工厂和纸机逐层找到使用位置，再选择关联织物。产品线分组帮助团队浏览成形、压榨和干燥等应用，同时保留纸机上下文。

每个产品还具有唯一的 MMP 编号，便于识别和查询。

## 将应用工程直接纳入报价流程

在报价中完成技术评审。销售可以将报价明细提交给应用工程师，减少通过 Excel、邮件或 Teams 反复交换技术参数的工作。

应用工程师可以：

- 查看纸机与使用位置资料。
- 选择或推荐织物设计。
- 完成对应产品的技术参数。
- 记录工程建议。
- 将完成的设计交回销售，继续定价与报价准备。
- 随报价历史保留设计决策。

工程交接是它与通用 CPQ 的核心区别之一：技术建议始终关联所支持的产品与报价。

## 为不同织物系列灵活配置技术参数

不同产品线需要不同的工程信息。管理员可以配置技术字段、分区、校验规则和选项，用于：

- 成形网（Forming Fabrics）
- 压榨毛毯（Press Felts）
- 干网（Dryer Fabrics）
- 靴压套（Shoe Press Sleeves）
- 上网带（Top Belts）
- 随业务需求扩展的其他产品系列

增加或调整技术参数，无需重新设计应用的核心结构。字段停用后，历史报价中已记录的参数值仍然保留。

## 标准价格与折扣审批，统一管控

**让销售高效推进报价，同时保持价格可控。** 将推荐设计与标准定价连接起来，分别记录申请折扣与批准折扣。

- 按生产基地和设计维护标准价格。
- 使用报价单统一币种，覆盖所有明细。
- 为每个报价版本保留**标准单价快照（Standard Unit Price）**。
- 记录申请折扣及申请原因。
- 记录批准折扣和审批决定。
- 查看审批历史，比较不同报价版本中的历史价格。

当前价格调整不会覆盖旧报价版本中的价格快照。

## 每一个报价版本，都有据可查

技术配置、价格或商务条件发生变化时，可以创建新报价版本，并保留之前的决策。

例如，**报价 2026-001** 可以依次形成：

- **V1 — 初始方案：**所选织物和首轮技术建议。
- **V2 — 设计调整：**更新后的参数及对应价格。
- **V3 — 折扣获批：**确认后的商务方案。

通过旧版本了解变更内容，并结合工作流和审计历史追溯操作人员、审批决定、历史价格与工程建议。

## 适配企业部署与管理要求

根据企业 IT 环境选择合适的部署方式：

- 支持私有云或本地部署，采用 Docker 交付。
- 支持 SQL Server 或 PostgreSQL 数据库。
- 通过角色权限管理销售、工程和审批职责。
- 保留审计历史与报价工作流记录。
- 按业务需要配置产品与设计参数。
- 提供 API 基础，按项目需求扩展系统对接。

<details>
<summary>技术详情</summary>

系统基于 .NET 10、Blazor Server、MudBlazor 和 Entity Framework Core 构建。Clean Architecture 分离领域、应用、基础设施与界面职责，并使用 Mediator、FluentValidation 和 Mapster 支持应用用例。

可复用的动态字段框架为产品与设计数据提供模板、字段定义、校验和历史值管理。Docker 部署与自动化测试支持一致的交付过程。

</details>

## 从一个聚焦的试点开始

先用真实报价验证流程，再逐步扩展。试点实施可以从以下范围开始：

- 一条产品线
- 部分客户
- 几台纸机
- 现有产品主数据
- 当前定价规则
- 一套报价或合同模板

与团队一起验证工程交接、价格管控和审批过程，再决定后续推广范围。
